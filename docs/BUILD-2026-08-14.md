## A real bug found and fixed during this build

The first screenshot pass (`step3-refusal-message.png`, pre-fix) showed the
step-3 panel with **no visible failure message** after an `sk_` refusal —
`index.html`'s `doStep()` called `showStep3(message)` *before*
`renderStepper()`, and `renderStepper()` rebuilds the entire panel's innerHTML
(a fresh, empty `#step3-msg` div included), silently wiping the message that
was just set. A second, related bug: on the *first* invalid (not
over-powered, just malformed) paste, no message showed at all, because the
old code only handled the `refused` and `alt_path`-present cases. Fixed by
reordering (render first, then set the message) and always showing
`r.data.message` for step 3 when present. Commit `ea84cf1`, re-verified with
a fresh screenshot (`step3-refusal-message.png`, current version) showing the
full refusal copy rendered inside the step-3 card. This is exactly the kind
of thing curl-only testing doesn't catch — worth the extra 15 minutes.

## How identity was tested without a real email round-trip

Rather than requiring an inbox (impractical for an unattended build/test
pass), tests used Supabase Auth's **Admin API** — `POST
/auth/v1/admin/generate_link` (type `magiclink`) returns a `hashed_token`
without sending mail; `GET /auth/v1/verify?type=magiclink&token=<hashed>`
consumes it and redirects with a real `access_token`/`refresh_token` in the
URL fragment — the exact mechanism `SOMA/tools/auth/README.md`'s own
ground-truth probe already uses to test the auth allow-list. This produces a
**genuine, fully-valid Supabase session JWT** for any address, used two ways:
as a bearer token directly against the functions (`test/e2e.sh`), and injected
into a real browser via `supabase.auth.setSession()` for the screenshots
(`docs/screenshots/`). The throwaway wrong-identity user was created and
deleted via the same Admin API; nothing persists from testing.

## What's mocked, and why (said honestly, per the build task's own permission)

- **Stripe liveness probe's SUCCESS branch** (`test/local-success-path.mjs`)
  mocks `global.fetch` for `api.stripe.com/v1/account` only, returning a
  canned 200. **No Stripe test-mode account is accessible in this estate** —
  checked: `ai-embassadors`' Netlify site (the one other repo with Stripe
  code) has **zero env vars set**, its `STRIPE_SECRET_KEY` is a placeholder
  default, never configured. The FAILURE branch of the same probe (TEST 6
  above) is proven for real against Stripe's live API — only a genuine
  `rk_test_`-prefixed key with real Stripe access would let a success case
  run for real. Minting one needs a Stripe account Mike controls; flagged as
  the one thing Locke/Mike could hand this build to close the gap.
- **`KEYDROP_NETLIFY_PAT`** reuses Mike's full-account Netlify CLI token
  rather than a purpose-minted one — Netlify PATs are account-scoped, not
  resource-scoped, so there is no API path to mint a narrower one
  headlessly. Detail + the exact Mike-gated fix: `SOMA/keys/KEYRING.md`.
- **`rrweb` demo recording via `_estate/bin/demo-record` hit WQ-295** (`demo-record`
  launches a fresh, unauthenticated browser context with no `--storage-state`
  support — the exact gap WQ-295 tracks). Substituted a direct Playwright
  script that authenticates via the real `supabase.auth.setSession()` API
  (not a workaround/hack — it's the SDK's own method) and captured static
  screenshots instead of a full interactive rrweb replay. The failed
  `demo-record` attempt left a near-empty `events.json` (2 events) at
  `_estate/demos/2026-08-14-keydrop-stepper-inert/` — left in place rather
  than force-deleted, for the record.
- **Closure acks (`lib/ack.mjs`)** — the integration point exists and is
  called on every completion, but the actual send transport isn't wired
  (would need `nodemailer` + `CLAUDE_GMAIL_APP_PASSWORD` as a Netlify env
  var, since a Netlify function runs off-Mac and can't shell out to
  `send_from_claude.py`). Deliberately left unimplemented rather than
  half-wired, per the hard rule "no outward sends" for this build — flipping
  `KEYDROP_LIVE=true` before this is finished throws loudly instead of
  silently no-op'ing.
